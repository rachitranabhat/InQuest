# PRISM — evidence-grounded investigation copilot

**ThunderHacks II · OLG Sponsor Challenge prototype.**

> **Independent prototype on synthetic data.** PRISM is not affiliated with OLG. It does not connect to, implement, reproduce or replace OLG's DART system or any OLG data source. Every player, account, retailer and transaction is generated by a seeded simulator. The AI never decides an outcome; a human reviewer does.

PRISM sits *after* an existing monitoring system. It takes an alert, gathers the case's evidence into an immutable registry, writes an investigation report in which **every sentence is a structured claim that cites evidence IDs and is checked by a deterministic validator**, answers case-scoped questions with citations, and records the reviewer's decision in an append-only audit trail.

```
Existing monitoring system → Alert → Evidence retrieval → Risk analysis → AI copilot
        → Evidence-linked report → Human investigator → Decision (audited)
```

## Quick start

Requirements: Python 3.11+ (3.13 tested), Node 20+ (22 tested).

```bash
# 1. Backend
python -m venv .venv
.venv\Scripts\activate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt

# 2. Frontend
cd frontend && npm install && cd ..

# 3. Optional: LLM mode. Copy .env.example to .env and set OPENAI_API_KEY.
#    Without a key everything runs in Demo (deterministic) mode.

# 4. Run both servers (API :8100, React :5174 with /api proxy)
python scripts/dev.py
#    open http://localhost:5174
```

Other launch modes:

| Command | What it does |
|---|---|
| `python scripts/dev.py --backend` | API only |
| `python scripts/dev.py --prod` | builds React, FastAPI serves it at http://127.0.0.1:8100 |
| `python backend/pipeline.py status` | dataset and schema status |
| `python backend/pipeline.py reset --yes` | backs up the DB to `backend/data/backups/`, then regenerates |

The dataset is generated once on first start and **never regenerated on restart**. Windows users can run `scripts\setup-windows.ps1` to do steps 1–2.

## What's in the app

| Screen | Purpose |
|---|---|
| **Investigation queue** | Table-first; filter by priority, status, alert type, channel, reviewer, dates; URL-shareable filters |
| **Case workspace** | Evidence (timeline, all evidence, relationships) · report · copilot + decision panel. Clicking a citation opens the evidence drawer, highlights the source transactions in the timeline and graph, and "Back to report" returns focus to the citation |
| **Relationship explorer** | Cytoscape graph of recorded relationships only (never infers player-to-player links from a shared retailer), with search, filters, zoom/fit/reset and a table alternative |
| **Reports & review history** | Append-only audit: action, reviewer, time, status change, report version, evidence hash, notes; PDF links |
| **Scenario lab** | Generates a fresh fictional subject, runs the monitoring rules, opens the case |
| **Analytics** | Counts computed from the database only; nothing estimated |

### Grounding guarantees (enforced in `backend/services/claims.py`)

- Every cited ID exists and belongs to this case
- Numbers, dates, times, retailer and place names must appear in the *cited* evidence
- Aggregated statements must cite an aggregate record
- Accusatory language and "absence as proof" are rejected
- Unverified claims are hidden by default and never shown as verified
- LLM output is validated, repaired once, and if it still fails the report is labelled **"LLM fallback (deterministic)"**, never passed off as LLM text

### Prioritisation

Priority (*Critical / High / Medium / Lower review priority*), the **prototype alert score** (0–100 rule-based measure of unusualness, **not a probability**) and evidence completeness are shown separately. No calibrated percentages are claimed.

### Review workflow

`New → Analysis Ready → Under Review → Information Requested → Closed — No Further Action | Escalated` (reopen allowed). Notes are required and validated on the server; idempotency keys prevent duplicate submissions; a stale status returns 409. Reviewer sessions are **simulated** (chosen from a list, labelled as such) — not authentication.

## Architecture

See [docs/architecture.md](docs/architecture.md). In short: FastAPI + Pydantic over the Python detection, evidence and reporting modules; SQLite with versioned migrations and immutability triggers; React 19 + TypeScript + Vite + Tailwind v4 + Radix + TanStack Query + Recharts + Cytoscape.

Branding (name, tagline, disclaimers, display timezone) lives in one file: `branding.json`.

## Limitations

- Synthetic data; detection rules were written alongside the simulator, so results say nothing about real-world performance. See [docs/evaluation.md](docs/evaluation.md).
- The validator checks consistency with cited evidence, not truth about the world, and its entity/number matching is lexical.
- Simulated reviewer sessions; no real authentication or authorisation.
- LLM mode requires your own OpenAI-compatible key; the key stays on the server.
